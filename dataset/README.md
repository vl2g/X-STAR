# X-STAR dataset card

> **Status:** the manifest, split lists and feature files are not yet
> distributed from this repository, and no download location has been
> decided. Source images must be obtained from their original providers (see
> [Source images](#source-images)); a preparation script and the Chinese subset
> mapping are included.

## Task

Text-to-image retrieval where the query and the scene text in the image may be
in different languages. For every test image there is one query per query
language; each query has exactly one relevant image, and retrieval is ranked
over the full test gallery.

## Image identifiers

- `filename`: relative path `<folder>/<name>.jpg`, e.g. `A/image_18.jpg`.
- `image_id`: `<folder>_<stem>`, e.g. `A_image_18`. All per-image feature files
  and query ID lists use this identifier.

## Query languages and fields

Each manifest record carries 13 query-language fields and 12 back-translated
fields:

| Field | Meaning |
|---|---|
| `english_query` | English scene-text-aware query generated for the image |
| `<lang>_query` (12 fields) | The query in Assamese, Bengali, Gujarati, Hindi, Kannada, Malayalam, Marathi, Odia, Punjabi, Tamil, Telugu or Chinese, obtained by translating the English query |
| `<lang>_to_english` (12 fields) | Machine translation of `<lang>_query` back into English |

The 13 evaluated query sets are `english_query` plus the 12
`<lang>_to_english` fields. CoLITE-CLIP and the CLIP baseline both consume the
English (or back-translated English) strings after whitespace collapsing; they
do not encode the native-script `<lang>_query` strings directly.

Query provenance (author-confirmed and from the paper draft): English queries
were generated by GPT-4 from each image and its English-translated scene text,
then translated into the other languages. The exact GPT-4 variant and the exact
translation-system versions used for every field have not been verified from
run logs; these provenance details remain unverified.

Exact duplicate images: 61 pairs of records share byte-identical image files,
25 of them across splits (15 test and 8 validation images equal a training
image). See [`../docs/dataset_integrity.md`](../docs/dataset_integrity.md) .

Known content notes from the audit:

- 311 `english_query` values contain non-Latin letters, usually a native-script
  scene-text phrase inside an otherwise English query.
- One record, `D_image_342` (train), has an `english_query` with no Latin
  letters at all. The GT-OCR and crops manifest variants carry a different
  English query for this record. This is recorded for review, not corrected.

## OCR inputs

OCR recognition and OCR translation are **external preprocessing**. The
release pipeline starts from English OCR lines supplied in the manifest and
encodes each line independently with the CLIP ViT-B/32 text encoder.

| Field / variant | Contents | Role |
|---|---|---|
| `ocr_lines_en` in the primary manifest | **Recognized OCR**: for BSTD images, IndicPhotoOCR line outputs translated to English; for the Chinese images, line-level text taken from RCTW-17 and translated to English (per the paper draft) | Primary input for training, evaluation and the reported results |
| `gt_lines_en` in the GT-OCR manifest variant | **Ground-truth OCR**: English lines derived from the manual BSTD text annotations for the 5,949 BSTD images; the 500 Chinese records reuse `ocr_lines_en` (`gt_source: ocr_fallback`) | Separate oracle-OCR experiment only |
| `crops` in the crops manifest variant | Per-line integer boxes for the recognized OCR | Auxiliary; not used by the main model |
| Corrected-OCR feature caches | Line embeddings from a post-processed OCR variant | Separate experiment only; no matching manifest has been identified |

Recognized OCR and ground-truth OCR must never be mixed in one experiment.
222 images have no recognized OCR line; all of their OCR slots are filled with
the model's learned null OCR token.

For the 5,949 BSTD images, the recovered merged translated-OCR artifact from
the original OCR run agrees with `ocr_lines_en` for every record after
whitespace collapsing and removal of empty lines (5,820 records are identical
before that normalization; 129 differ only in whitespace or empty lines).

## Source images

X-STAR does not assume permission to redistribute any source image. Obtain the
images from their providers under their terms, then place them under the
X-STAR folder layout.

### Bharat Scene Text Dataset (folders A–G, I–L; 5,949 images)

- Provider: [Bharat Scene Text Dataset](https://github.com/Bhashini-IITJ/BharatSceneTextDataset)
  (scene-text detection images).
- Mapping: the X-STAR `filename` is the image's relative path in the BSTD
  detection layout (`<folder>/image_<n>.jpg`).
- Note: X-STAR's train/validation/test split is its own and differs from the
  BSTD split.
- Verification status: filename correspondence only. Image bytes have not yet
  been compared with a fresh BSTD download.

### RCTW-17 (folder N; 500 images)

- Provider: [RCTW-17](https://rctw.vlrlab.net/) (Reading Chinese Text in the
  Wild). No formal named license is specified; reported original-author reuse permission is described in [licensing](../docs/licensing.md).
- Exact mapping: `N/image_<k>.jpg` ← RCTW-17 `raw/train_images/image_<k>.jpg`
  (identical file name, taken from the RCTW-17 training images).
- Verification status: all 500 X-STAR Chinese images match their RCTW-17
  source files byte for byte (SHA-256). The per-file list is
  [`rctw17_chinese_mapping.csv`](rctw17_chinese_mapping.csv).

### Preparation

[`scripts/prepare_dataset.py`](../scripts/prepare_dataset.py) places
separately obtained images under the X-STAR layout, using the manifest's fixed
records (the split is never re-drawn) and
[`rctw17_chinese_mapping.csv`](rctw17_chinese_mapping.csv) for folder N. It
downloads nothing, only reads the source datasets, never overwrites an existing
file (an identical file is accepted, a different one is reported) and verifies
the 500 Chinese images by SHA-256.

```bash
# Report what would be done; write nothing.
python scripts/prepare_dataset.py --manifest /path/to/XSTAR_final_manifest2.json \
    --bstd-root /path/to/BharatSceneText/detection --rctw-root /path/to/RCTW-17 \
    --output-root /path/to/XSTAR_dataset --dry-run
# Copy (or --link symlink/hardlink) the images, then check an existing layout.
python scripts/prepare_dataset.py --manifest /path/to/XSTAR_final_manifest2.json \
    --bstd-root /path/to/BharatSceneText/detection --rctw-root /path/to/RCTW-17 \
    --output-root /path/to/XSTAR_dataset
python scripts/prepare_dataset.py --manifest /path/to/XSTAR_final_manifest2.json \
    --bstd-root /path/to/BharatSceneText/detection --rctw-root /path/to/RCTW-17 \
    --output-root /path/to/XSTAR_dataset --verify-only
```

The manifest itself is not yet distributed from this repository. Each split
list equals the sorted filenames of that split in the manifest;
[`scripts/validate_dataset.py`](../scripts/validate_dataset.py) checks a layout
and, with `--check-features`, its cached features.

## Feature files

Feature extraction scripts write the same file layout as the original cache
(see [`configs/paths.example.yaml`](../configs/paths.example.yaml)). OCR line
embeddings written by
[`scripts/extract_ocr_features.py`](../scripts/extract_ocr_features.py) use the
pickle-free `xstar-ocr-lines-v1` format, one `<image_id>.npz` per image:

| Member | Contents |
|---|---|
| `E` | float32 `[L, 512]`, one L2-normalised CLIP ViT-B/32 text embedding per OCR line |
| `lines` | Unicode `[L]`, the encoded line strings in order (whitespace-collapsed, empty lines dropped) |
| `format` | the string `xstar-ocr-lines-v1` |

Images without OCR lines have `L = 0`. The original cache files store `E`,
pickled `tokens` and `scores`; the package reads their `E` without unpickling.
